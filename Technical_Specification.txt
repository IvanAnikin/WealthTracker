
Technical Specification
Personal Finance Aggregator (Open Banking, Python, Web UI)
1. Project Objective

Build a web-based personal finance aggregation application that:

securely connects to multiple banks using PSD2 Open Banking (AIS, read-only),

synchronizes accounts, balances, and transactions,

computes account balances at arbitrary historical dates,

provides cashflow and spending reports,

supports data export (CSV/XLSX),

is implemented in Python with a web UI.

The system must never handle bank credentials and must rely on third-party Open Banking aggregators for bank access.

4. Open Banking Integration Model
4.1 Integration Strategy

Use a licensed Open Banking Aggregator.

Do not integrate directly with bank APIs.

AIS only (read-only).

4.2 Consent Flow (AIS)

User selects a bank.

Backend creates a requisition/consent via aggregator API.

User is redirected to bank SCA (Strong Customer Authentication).

Bank returns consent to aggregator.

Backend retrieves connected accounts.

Backend periodically pulls balances and transactions.

4.3 Security Constraints

No bank credentials are stored or processed.

All connections use HTTPS.

API keys stored in environment variables.

Aggregator tokens encrypted at rest.

7. Balance-at-Date Calculation
Definition

Compute account balance at date D using booked transactions only.

Algorithm
balance(D) =
    initial_balance_amount
  + SUM(transaction.amount)
    WHERE
      transaction.booking_date > initial_balance_date
      AND transaction.booking_date <= D
      AND transaction.status = 'booked'

Notes

Pending transactions are excluded by default.

Balances are computed per account currency.

Cross-currency aggregation is optional (v2).
